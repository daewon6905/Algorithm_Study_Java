난이도: lvl2

난이도에 비해 어렵다. 처음에 잔돈구하는 문제 처럼 bfs로 생각했었는데 경우의 수가 너무 많아 메모리가 터짐.

그리디로 풀어야 하는데, 10의 제곱 수 단위로 층을 이동하기에 자릿수를 떠올리는 걸 기억 해두자.

2554로 예를 들면 1의 자리부터 0을 만들어 간다고 생각하면 된다. 

4는 10으로 가는거 보다 0으로 가는것이 가깝기에 2554 -> 2550을 하여 다음 자릿수를 올리지 않고 
정답에 4를 더한다. 

그 다음이 까다롭다. 255에서 5는 위로 가던 아래로 가던 거리가 같다. 즉 자릿수를 올릴 것인지 유지할 것인지는
다음 숫자가 5를 기준으로 작냐 크냐에 달렸다. 그 다음도 5이므로 조건을 next>=5이면 자리를 올리고, 미만이면 내린다고 하면, 
현재 자릿수 remainder가 5이면, if(next>=5) 이면 answer+=(10-remainder) 하고 storey에 10을 더해주어 다음 자릿수를 올려준다.
if(next<5) 이면 answer+=remainder을 하고 다음으로 넘어간다 (자릿수 변동 x) 이 과정을 storey가 0보다 클 동안 진행하면 해결이 가능하다.



**양방향 연산의 함정:** $+10^k$와 $-10^k$가 모두 가능해서 상태 공간이 무한해 보이고, 자연스럽게 최단 거리를 찾는 BFS나 거스름돈 DP를 먼저 떠올리게 됩니다.

**낮은 자리부터의 독립성:** 높은 자리는 낮은 자리를 건드릴 수 없지만, 낮은 자리의 올림은 높은 자리에 영향을 준다는 단방향 종속 관계를 간파해야 1의 자리부터 쳐내는 발상이 나옵니다.

**경계값 5의 예외 처리:** 보통의 반올림은 $5$일 때 단순 올림이지만, 여기서는 비용이 같다는 특성 때문에 "다음 자릿수까지 미리 내다봐야 한다"는 Look-ahead 조건이 붙어 직관을 한 번 더 꼽니다.실전에서는 이런 유형을 마주했을 때 아래 순서로 접근하면 그리디 접근법을 빠르게 눈치챌 수 있습니다.

**제약 조건 확인:** $N \le 10^8$이므로 $O(N)$이나 상태 수가 큰 BFS/DFS는 100% 터진다고 판단합니다.

**연산 단위 확인:** 이동 단위가 $1, 10, 100\dots$처럼 10의 거듭제곱으로 딱 맞아떨어지면 자릿수 분해(진법 문제)일 확률이 매우 높습니다.

**가장 작은 단위부터 고정:** 큰 자릿수를 아무리 더하고 빼도 1의 자리 수는 바꿀 수 없으므로, "선택의 여지가 없는 1의 자리부터 확정 짓는다"는 불변량을 찾는 것입니다.
